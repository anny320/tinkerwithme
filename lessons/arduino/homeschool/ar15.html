Simon Says Memory Game

Advanced · about 120 minutes · ages 13–15

1. Session Overview

The grand finale! {{child}} builds the classic "Simon" memory game: the Arduino flashes a growing sequence of colours with matching tones, and the player repeats it using buttons. This project ties together everything — arrays, loops, functions, input, output, sound and game logic — into a real, playable game.

2. Learning Objectives

  • Store and grow a sequence using an array.
  • Compare player input to a stored pattern.
  • Structure a program into clear functions.
  • Handle game states: play sequence, get input, win/lose.

4. Flexible Schedule (planned session: {{duration}})

  • Warm-up (10 min): Play the memory game verbally; discuss how to store a growing list.
  • Build (40 min): This is a big wiring job — 4 LEDs, 4 buttons, buzzer. Work methodically.
  • Code in stages (50 min): Light each LED, then play a sequence, then add input checking.
  • Play & polish (20 min): Add win/lose feedback and beat a high score.

5. Project Breakdown

Step-by-step

  1. Wire and test all 4 LEDs and 4 buttons individually first — don't code the game until each part works.
  2. Add the buzzer.
  3. Upload the full game and play. The sequence grows by one each round.

Full working code

// Simon Says — TinkerWithMe
int leds[]    = {2, 3, 4, 5};
int buttons[] = {8, 9, 10, 11};
int tones[]   = {262, 330, 392, 494};  // C E G B
int buzzer = 12;

int sequence[100];
int level = 0;

void setup() {
  for (int i = 0; i < 4; i++) {
    pinMode(leds[i], OUTPUT);
    pinMode(buttons[i], INPUT);
  }
  pinMode(buzzer, OUTPUT);
  randomSeed(analogRead(A0));
}

void flash(int i) {
  digitalWrite(leds[i], HIGH);
  tone(buzzer, tones[i], 300);
  delay(350);
  digitalWrite(leds[i], LOW);
  delay(150);
}

int waitForPress() {
  while (true) {
    for (int i = 0; i < 4; i++) {
      if (digitalRead(buttons[i]) == HIGH) {
        flash(i);
        while (digitalRead(buttons[i]) == HIGH);  // wait for release
        return i;
      }
    }
  }
}

void gameOver() {
  for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 4; j++) digitalWrite(leds[j], HIGH);
    tone(buzzer, 120, 300); delay(300);
    for (int j = 0; j < 4; j++) digitalWrite(leds[j], LOW);
    delay(300);
  }
  level = 0;   // restart
  delay(1000);
}

void loop() {
  // Add a new random step
  sequence[level] = random(0, 4);
  level++;

  // Play the whole sequence
  for (int i = 0; i < level; i++) flash(sequence[i]);

  // Player repeats it
  for (int i = 0; i < level; i++) {
    int press = waitForPress();
    if (press != sequence[i]) { gameOver(); return; }
  }
  delay(700);  // short pause, then next round
}

Common mistakes & how to fix them

  • Buttons register twice: the "wait for release" line handles this — make sure it's present.
  • Random but same each power-up: keep A0 unconnected for randomSeed.
  • An LED/button pair mismatched: confirm pin order matches the wiring.
Success looks like: a playable game where the sequence grows each round and a wrong press ends the game. {{child}} can explain how the array remembers the pattern.

6. Conversation Starters

  • "How does the array let the game 'remember' a growing sequence?"
  • "What would you change to make the game harder as it goes on?"

7. Extensions & Challenges

  • Speed the sequence up as the level rises.
  • Show the score by flashing the level number, or add a two-player mode.

8. Troubleshooting Guide

  • Game feels unresponsive: check every button's pull-down resistor — a floating input causes chaos.
  • One colour never accepts input: that button's wiring is off; test it with a simple read sketch.

9. Parent Guidance Tips

{{parent}}, this capstone is ambitious — expect it to take the full session and possibly a second sitting. The secret is building in stages and testing each piece before moving on. Celebrate reaching a playable game; it's a genuine achievement that pulls together months of learning. Then challenge {{child}} to beat your high score!
